# SUPER-GONGIK — Boss Cinematic (isolated workspace)

A 90-second, fully procedural 3D boss fight: a Korean social-service agent (사회복무요원) against an
enormous winged white dragon on a basalt headland at sunset. Everything — every mesh, texture,
animation curve, particle, light, grade and note of music — is generated by code. There are no
models, images, sound files, generative-video APIs or AI-produced frames anywhere in the pipeline.

This folder is **not** part of the pnpm workspace (`pnpm-workspace.yaml` lists only `apps/*` and
`packages/*`) and touches nothing in `apps/` or `packages/`. The production app is unchanged.

|             |                                                                     |
| ----------- | ------------------------------------------------------------------- |
| Engine      | three.js r170 (WebGL 2), custom GLSL, no other runtime dependency   |
| Length      | 90.000 s, 30 fps, 2,700 frames, 32 shots                            |
| Picture     | 2.39:1 rendered at 1920×804, letterboxed into 1920×1080 H.264       |
| Sound       | 48 kHz stereo, synthesised offline in Node from the same beat sheet |
| Determinism | every frame is a pure function of its frame number                  |

## Commands

```bash
cd cinematic/boss-battle
npm ci                   # three.js only
npm run preview          # prints a URL: real-time playback in a WebGL2 browser (?play, ?play&t=45, ?f=1380)
npm run score            # out/score.wav
npm run render:draft     # 640×268 preview MP4, ~20 min on 4 CPU cores
npm run render           # 1920×1080 (2.39:1 picture) MP4 + .render.json (per-frame hashes, timings)
npm run qa               # determinism, sanity, SSIM regression vs qa/baselines, timeline + audio checks
npm run qa:update        # rewrite baselines after an intentional visual change
npm run sheet            # contact sheet across the film
```

The tools drive headless Chromium through Playwright (`require('playwright')`), with WebGL running on
SwiftShader (CPU). Playwright is expected to be installed on the machine (it is in the cloud
container this was built in); it is not a dependency of this package. FFmpeg must be on `PATH`.

## Architecture

```
src/
  util.js       seeded PRNG, value noise, monotone-cubic keys, envelopes (pure; shared with Node)
  timeline.js   beat sheet, 32-shot edit list, global envelopes (pure; shared with Node)
  glsl.js       GLSL noise + the dusk sky model (sky dome, sea reflection and clouds agree on it)
  shaderkit.js  extends three.js PBR materials with procedural colour / bump / emission
  world.js      sky, sea, terrain + cliff, plaza, grass, columnar basalt, dry-stone wall, lamps, bench,
                closed-form destruction (ballistic arcs with two bounces, any frame in any order)
  dragon.js     the dragon: spine generators, body tube, sculpted head, wings, IK legs, choreography
  agent.js      the agent: joint hierarchy, uniform, insignia, seal-hammer, pose library, choreography
  fx.js         GPU particles (dust, sparks, seal energy, grit, embers, breath), beams, ward, shockwaves,
                lightning, billboard cloud bank, effect lights
  camera.js     one function per shot, reading the actors' state after they update
  post.js       HDR MSAA -> 5-level bloom -> sun shafts -> ACES + grade -> lens -> titles -> sRGB
  main.js       boot, light rig, grade timeline, window.__renderFrame(n)
audio/score.mjs score + foley, synthesised sample by sample, mixed, reverb, normalised, WAV
tools/          render.mjs (parallel render -> FFmpeg MP4), qa.mjs, sheet.mjs, still.mjs, probe.mjs, preview.mjs
qa/baselines/   reference frames for SSIM regression (640×268)
```

### Determinism

Nothing reads a clock or `Math.random`. Every value on screen is a function of film time
`t = n / 30`: keyed curves (monotone cubic, no overshoot), seeded noise, and closed-form simulation
(debris arcs and bounces solved analytically at load; particles evaluated in the vertex shader from
per-particle seeds). Grain is seeded by the frame number. That is what lets `render.mjs` split the
film across independent browser processes, and it is checked by `qa.mjs`.

### The dragon (`src/dragon.js`)

- **Two spine generators, blended.** _Path mode_: the head follows a keyed flight path; the body is
  the last 34 m of that path (arclength table precomputed at 60 Hz), with a travelling swim wave and
  banking from lateral acceleration. _Local mode_: a root transform (position, yaw, pitch, roll)
  carries a body shape blended from a pose library (`stand`, `roar`, `tailSwing`, `rearClaw`,
  `strike`, `inhale`, `breath`, `takeoff`, `reel`, `hover`, `bow`, ...). Control points are resampled
  at fixed arclength so the body never stretches.
- **Body**: 96 rings × 22 segments rebuilt per frame along parallel-transport frames, radius profile
  from neck to tail, flattened belly; procedural overlapping scales, belly plates, dorsal tint,
  throat glow during the breath, warm rim transmission from the low sun.
- **Head**: sculpted from primitives (skull, tapered snout and jaw wedges, brow, cheek and ridge
  forms), teeth, two pairs of tapered horns with colour gradient, cheek frills, animated whiskers,
  mane, slit-pupil eyes (shader), glowing mouth interior, and the seal mark that appears at the slam.
- **Wings**: arm + four fingers per side with spread/fold, flap with span-wise lag, sweep for the
  dive; membrane panels with scalloped trailing edges and billow from flap velocity; veins and
  sun transmission in the membrane shader.
- **Legs**: two-bone analytic IK, feet planted on the terrain, claw strike override.

### The agent (`src/agent.js`)

A 1.75 m joint hierarchy (hips, spine, chest, neck, head, shoulders, elbows, wrists, hips, knees,
ankles) built from rounded boxes and capsules, driven by a pose library (idle, walk and run cycles,
brace, draw, ready, slide, parry, knocked, ward, deflect, climb, leap, swing, smash, fall,
superhero landing, reach, cap tip) with cross-fades, plus a keyed root path.

**Uniform.** It follows the project's own canonical character in
`docs/design/app-icon/png/super-gongik-icon-v3-512.png`: navy cap with brim and badge, blue
short-sleeve work shirt (collar, placket, pockets), Korean flag patch on the left chest, round
emblem on the left sleeve, black belt, dark navy trousers, black boots — plus a name tag. The
Taegukgi is drawn procedurally (taegeuk and the four trigrams). **Not verified against the Military
Manpower Administration's official dress regulation (복제 기준):** the official spec could not be
retrieved from this environment, so exact colours and insignia placement may differ from the
issued uniform. The name tag reads "SOCIAL SERVICE" because the render machine has no Korean font.

## How this relates to Crimson Loong

[ChetasLua/crimson-loong](https://github.com/ChetasLua/crimson-loong) was studied for its
architecture. Its repository has **no licence file** (only three.js's MIT licence for the vendored
library), so none of its source was copied. This is a new implementation; the ideas that informed
it, and where this one differs:

| Area      | Crimson Loong                                                                                                     | This film                                                                                                                                                                   |
| --------- | ----------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rendering | Scripts concatenated into one HTML file; HDR target, AO, bloom, sun shafts through haze, grade, lens extras       | ES modules + importmap; HDR MSAA, 5-level bloom, radial sun shafts, ACES + lift/gamma/gain, fringe, shock ring, grain. No AO pass                                           |
| Geometry  | SDF sculpting kit + surface-nets mesher; displaced parametric rock; architecture, flora, water with planar mirror | Primitives, wedges and tapered tubes; heightfield terrain with columnar-basalt shading; analytic sea with sky reflection. No SDF mesher, no planar mirror                   |
| Dragons   | Body as the last metres of the head's rail, swim wave, impulses, aim; plate-scale shader; seat zones on rock      | Same rail idea for flight, plus a separate pose-library generator for ground acting and a blend between them; wings with membranes (Crimson's loongs are wingless); IK legs |
| Animation | Everything a pure function of film time; tables built once at load                                                | Same principle; closed-form debris instead of tables                                                                                                                        |
| Camera    | One continuous 90 s crane on monotone-cubic keys                                                                  | A 32-shot edit, each shot a function of the actors' state                                                                                                                   |
| Audio     | Synthesised in a Web Worker in the page, played live                                                              | Synthesised offline in Node to WAV, muxed into the MP4                                                                                                                      |
| Capture   | Headless Chrome daemon on a real GPU, JPEG/PNG stills, WAV export                                                 | Headless Chromium on SwiftShader, parallel workers piping JPEGs into FFmpeg segments, concat + mux                                                                          |

## QA

`npm run qa` (results in `qa/report.json`, frames + contact sheet in `qa/current/`):

1. Timeline invariants (shot order, minimum shot length, 90 s × 30 fps, beats inside the film).
2. Determinism: a frame rendered, then after jumps across the film, then again must be byte-identical.
3. Sanity on one frame per shot plus eight key beats: not black, not blown out, not flat.
4. Visual regression: SSIM ≥ 0.97 against `qa/baselines/*.jpg`.
5. No page or WebGL errors.
6. Score: exactly 90 s, the slam and the landing hits land on their frames (energy ratio), loudness
   in [−20, −10] LUFS with true peak below 0 dBFS.

Baselines were produced on SwiftShader. A different GPU/driver will rasterise slightly differently,
so expect regressions to need `qa:update` on a new machine; determinism holds per machine.

## Limitations and unfinished work

Stated plainly, as of this version:

- **Stylised, not photoreal.** Characters are built from primitives (capsules, rounded boxes, wedges,
  tapered tubes), not sculpted or rigged meshes. The agent reads as an articulated action figure; his
  face has no expression rig. The dragon's head is assembled from primitives and close-ups show it.
- **No skinning.** The agent's limbs are rigid segments with visible joints; the dragon's body is a
  rebuilt tube (smooth), but its legs and wing bones are capsules.
- **Animation is keyed, not simulated.** Poses cross-fade; there is no physics, no cloth, no foot
  IK for the agent (feet can slide a little), and contacts (claw on hammer, seal on brow) are placed by
  hand from the beat sheet, not by collision.
- **Destruction is pre-fractured.** Basalt columns break at their natural joints and fly on analytic
  arcs with two bounces; pieces do not collide with each other, and there is no runtime fracture.
- **"Volumetric" light is screen-space.** Sun shafts are a radial blur of the bright pass; the breath
  beam is an additive shaded cylinder plus particles; fog is exponential. No ray-marched volumes, no
  ambient occlusion, no planar water reflection (the sea reflects the analytic sky only).
- **Slow motion is authored, not a time remap.** The leap is keyed slower; particles keep real time.
- **Text is Latin only.** The render container has no Korean font, so the name tag and titles are in
  English.
- **Uniform not verified against the official 복제 기준** (see above).
- **Audio is synthesised and was checked by measurement (waveform, loudness, event alignment), not by
  listening.** Instrument timbres are basic subtractive/additive synthesis.
- **Render cost.** On 4 CPU cores with SwiftShader the 1080p render takes about 80 minutes; a real
  GPU would be far faster. Real-time playback (`?play`) is not tuned for 60 fps.
- **Regression baselines are machine-specific** (SwiftShader); other drivers need `qa:update`.
- **CI does not render the film.** `npm run qa` is a local tool; it is not wired into the repo's
  GitHub Actions.
